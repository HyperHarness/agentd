# agentd 接入与接口行为约定

日期：2026-10-28。状态：从零开发的候选设计，尚未实施。返回[架构总览](../SOFTWARE_ARCHITECTURE_PROPOSAL.md)。产品范围与 R/D/H/P/F 标签以[需求基线](../PRODUCT_REQUIREMENTS_BASELINE.md)为准；本文拥有本主题的行为规则，字段与路由由[可执行契约](../../specs/agentd_v1/README.md)维护。

## 1 前后端开发边界与统一发布

**[R 已确认，2026-10-28]** Dashboard 前端与 agentd 后端分为两个开发模块，先确定交互合同，再分别实现；仍属于同一产品、同一发布版本，不拆成两个独立服务。后台按[模块与数据所有权](../SOFTWARE_ARCHITECTURE_PROPOSAL.md#模块与数据所有权)继续划分深模块，不能因前后端分工重新集中为无边界的大服务。

| 模块 | 拥有的责任 | 不承担的责任 |
| --- | --- | --- |
| Dashboard 前端 | 页面、表单草稿、有限本地校验、操作提示、连接和快照展示、结果核对 | 不推断权威任务状态、不自行决定调度/权限、不逐步编排升级、不保存第二份任务事实 |
| agentd 后端 | 权威校验、权限、配置版本、任务状态、调度、审核、统计与持久化；通过 U 执行生命周期操作 | 不决定视觉布局；不要求前端拼装内部租约、锁或数据库步骤 |
| 共同交互合同 | 业务动作、输入输出、权限、版本/幂等、异步进度、错误及断线恢复 | 不为每个按钮单独造一个 API，不用前端约定代替服务端检查 |

前端可使用合同派生的固定样例并行开发，但样例不算真实验收。尽早联调“页面配置 worker → 主线经 MCP 提交 → 真实执行与独审 → 页面读取结果”，不能等两个模块各自完成后才首次接通。发布包包含匹配的前端静态资源和后端；开发调试可独立运行，正式服务仍由 daemon 提供页面。页面检测到 API/发布版本不兼容时提示刷新或修复，不继续按旧字段发出变更。

## 2 一次接入

用户在 Dashboard 配置项目、worker 池以及主线和 reviewer 的既有根线程。主线负责通过已有客户端创建独立 reviewer 根，Dashboard 完成对应角色连接和通知目标配置，不在聊天中交换明文凭据。

Dashboard 按角色生成 CLI/MCP 连接配置，引用私有凭据来源；agent 不需要填写管理员凭据、服务内部路径或资源拓扑。项目与角色在连接时绑定，日常工具无需反复填写 project_id。多项目使用明确的独立连接别名，避免隐式切换上下文。

**[R 已确认，2026-10-28]** 使用同一套 MCP bridge 实现，配置 `agentd_lead` 和 `agentd_reviewer` 两个固定角色连接；分别自动加载各自凭据。主线与独立 reviewer 根只启用对应连接。连接名称和客户端启停用于防止身份混用，后端仍校验凭据，不相信请求自报角色。凭据校验封装为模块内部函数，日常使用无须用户或模型传入 token、执行登录工具或逐步完成鉴权。

客户端的连接选择与后端授权是两层职责；不提供切换角色的业务工具，不把两个入口绑定到同一管理凭据。一次接入后，用户直接使用业务动作；凭据过期、撤销或接线缺失时返回可行动的连接错误，由 Dashboard 或受信本地入口处理，不要求模型索取或粘贴密钥。

连接的签发、撤销和根重绑遵循[接入与接口行为约定](#8-基本权限与信任矩阵)，不能仅依靠线程登记或初始化时的一次认证。连接后调用 `get_context()`，返回项目、角色、服务是否可用、worker 池是否已配置、通知能力和当前需要处理的事项。它只检查和说明已有配置，不登录、不创建根线程、不修改权限、不调用模型。

根线程登记不代表在线，也不代表通知能力已验证。Dashboard 分别展示配置是否完整、连接检查结果和实际收件/领取观察。

## 3 主线

`submit_task` 可选传依赖和原任务关联。已有项目配置提供仓库与默认工具/MCP，任务只描述偏离默认的必要输入需求；省略项在提交事务中展开为固定项目版本，queued 任务不读取后来修改的默认项。不把完整 worker 配置塞进任务参数。代码任务必须解析到明确 base commit，不能把未知仓库状态默认当成有效输入。

`resume_task` 不成为任意配置修改接口。用户在 Dashboard 调整 worker 资源，任务详情再给出当前可用的继续动作。改变目标、难度、验收或需要重新分配模型时，由主线提交关联新任务。

工具签名、必需参数和各入口映射见[生成 API 参考](../../specs/agentd_v1/generated/API_REFERENCE.md)。

## 4 独立 reviewer

`next_review` 是有副作用的领取操作，不伪装成只读查询。只读查看使用 `get_inbox`。默认一个 reviewer 身份同时持有一项，重复调用不会悄悄领取多项。领取响应丢失时，同一 request_key 能找回原结果。

review_handle 是服务签发的候选与租约引用，不是可转交的身份凭据。调用仍校验连接角色、项目、当前绑定和撤销情况。reviewer 不需要自行填写 task_revision、candidate_hash、lease_version 等内部字段，也不能通过旧 handle 审核新候选。

工具签名、必需参数和各入口映射见[生成 API 参考](../../specs/agentd_v1/generated/API_REFERENCE.md)。

## 5 公共只读能力

`get_request_result(request_key)` 与 `get_operation(operation_id)` 对应 B13/B14，只查询当前身份获准的操作；reviewer 不因此获得任意任务查询权限。

主线与 reviewer 仅看到各自工具面。worker 的开发工具仍由原生 Claude Code 提供；执行适配器接收候选，不把 agentd 管理工具、主线接口或 reviewer 凭据注入 worker。

**[D 待评审]** Dashboard 快照携带观察时间及一致游标；断线、无权、过期与空结果分开显示。项目、身份或表单版本变化后旧响应失效；缺页或游标回退重新取快照，不能靠事件猜当前状态。保存后断线用原 request_key 查询结果，重连不自动重放写入或启动新服务。用乱序响应、锁定后迟到响应、保存后断线及恢复库游标回退验收。

工具签名、必需参数和各入口映射见[生成 API 参考](../../specs/agentd_v1/generated/API_REFERENCE.md)。

## 6 典型调用和结果

主线正常只需 `submit_task`，收到通知后调用 `get_inbox` 和 `get_task`。无需再调用 delegate、queue_review、approve 或 adopt。

reviewer 的基本路径为 `next_review` → 按需 `read_artifact` → `submit_review`，完成后继续领取，直到 empty。需要独立运行验证时，按[独立审核材料、验证证据与有界租约](TASK_AND_REVIEW_PROTOCOL.md#8-独立审核材料验证证据与有界租约)在自己的副本检查并用 `upload_review_evidence` 保存验证记录；租约过期后显式重领同候选并复核。遇到无法审核的情况调用 `defer_review`，不能为了结束领取而提交 REJECT。

对应的机器可读示例移至 [examples](../../specs/agentd_v1/examples/)，由契约检查器校验。

动作引用只避免让模型拼版本参数，不授予新的权限，也不承诺动作必然成功。引用过期返回明确冲突及重新读取任务的指引；服务不能默默把旧请求改成对新候选的操作。

## 7 HTTP 与 CLI 映射

HTTP 是 Dashboard、CLI 和 MCP bridge 的共同传输。完整方法、路径、角色和客户端映射由 [operations.py](../../specs/agentd_v1/operations.py) 定义，并生成 [API 参考](../../specs/agentd_v1/generated/API_REFERENCE.md)；本文不另抄一份路由表。B16 renew 仅供适配层，不成为要求模型调用的心跳工具。

Dashboard 管理身份复用获准的任务/统计/成果用例，但不能提交独审判决。两个 MCP 连接使用同一路由，由后端凭据确定身份。CLI 从本地回执带入 handle 或动作引用时，必须绑定原项目和身份，不能使用全局“最后一个任务”。

V0 管理入口具体化在操作注册表中；V1 生命周期 HTTP 和主动模型探针在对应阶段补齐。首次安装及停机期间交给本地 CLI/U，不要求 HTTP 先恢复。内部认证函数和静态资源不计为额外业务操作；显示按钮或工具名不授予权限。

## 8 基本权限与信任矩阵

**[D 待评审]** 这是兑现既有角色边界的最小合同，不建设组织 IAM 或恶意多租户平台。信任安装该服务的 OS 用户及其本地管理员；不信任请求中自报的 role、project_id、thread_id 或任意文件路径。凭据拥有者在授权范围内能操作，原生 worker 不获得主线/reviewer/admin 凭据。

| 操作 | Dashboard 管理身份 | 主线身份 | reviewer 身份 | worker 执行身份 |
| --- | --- | --- | --- | --- |
| 配置 worker/relay/资源、签发撤销角色和根绑定 | 允许，限该本机实例 | 禁止；只读取本项目必要摘要 | 禁止 | 禁止 |
| submit/get/list/resume/cancel Task | 可通过同一业务用例管理授权项目，不绕过规则 | 允许，限授权项目 | 禁止写任务；只读当前获准审核合同 | 不调用管理 API，只收到本次 Task 输入 |
| next_review / submit_review / defer_review | 不以 admin 凭据提交独审判决 | 禁止 | 允许，须当前独立 reviewer 绑定及租约 | 禁止 |
| reviewer 证据上传 / renew | 禁止冒用 reviewer 身份 | 禁止 | 仅当前候选和有效租约；renew 由连接层执行，仍逐次认证 | 禁止 |
| 读取 artifact | 允许授权项目并受文件边界约束 | 本项目可见成果和允许的诊断 | 当前审核获准的候选/证据；历史读取范围另按授权 | 仅本次执行明确交付的输入，不能任意查询其他任务 |
| 提交候选 | 不手工代造 worker 交接证明 | 禁止冒充 worker | 禁止 | 经本次执行专用结果通道，由适配器校验发布 |
| inbox/统计 | 按管理项目读取 | 本项目主线事项与统计 | 本角色审核事项；不读其他角色消息 | 无全局 inbox |
| 非敏感配置导出/备份维护 | 允许，受维护及数据合同约束 | 不可获取全局配置或凭据 | 禁止 | 禁止 |

角色来自服务认证，不由工具名或 URL 决定。admin 并不等同于独立 reviewer；需要独立审核时仍使用不同角色凭据和根上下文。同一 OS 用户可读取私有文件、替换程序，故不承诺抵御恶意同 UID 或恶意管理员；线程 ID 和凭据分离也不能证明模型推理在语义上完全独立。

#### 内部认证与授权函数

**[R 已确认]** 身份处理由接入模块内部调用，公开 MCP 工具参数只包含业务数据。**[D 待评审]** 以下为内部函数职责示意，不是新增公开 API，函数名和签名可在实现中调整：

| 内部调用 | 所属位置 | 输入与结果 |
| --- | --- | --- |
| `load_connection_credential(connection_ref)` | CLI/MCP bridge 的连接层 | 从所选连接的私有来源加载凭据，随受支持的 HTTP 认证机制自动发送；不写入工具参数、提示词、普通日志或返回值 |
| `authenticate_request(request)` | 后端统一接入层 | 校验凭据或 Dashboard 会话、有效期、撤销及绑定代次；产生受信 `AccessContext`，含稳定身份、角色、项目范围与授权代次，不含明文凭据 |
| `authorize_action(context, action, resource)` | 接入模块提供、业务用例调用 | 校验当前角色和项目能否操作目标；允许或返回稳定的权限错误，调用方不能自行构造角色绕过 |

正常调用链为：业务工具 → bridge 自动附带连接凭据 → 后端认证得到上下文 → 用例授权检查 → 业务操作。HTTP 直连、CLI、MCP 和 Dashboard 复用相同服务端规则；Dashboard 使用自身管理会话，不借用 reviewer 身份。

身份验证不替代业务前置条件：审核租约、候选绑定、任务终态、取消意图和版本检查仍由各深模块负责。授权撤销或根重绑后，旧上下文不能无限缓存；准备耗时操作后及提交关键事务时重核当前授权代次，与[共同状态与事务](RELIABILITY_AND_STORAGE.md#4-共同状态与事务)合同一致。失败返回 NOT_AUTHORIZED 等有限错误，不自动换成管理员凭据或为已撤销身份重新签发。

最小验收：主线与 reviewer 分别调用正确工具；互换角色调用被后端拒绝；直接 HTTP 绕过工具隐藏仍被拒绝；撤销及重绑后旧连接失效；重连按原凭据和 request_key 核对操作；用户与模型的正常调用无凭据字段。该设计不增加账号系统或独立认证服务。

## 9 凭据与连接生命周期

**[D 待评审]** 默认仅监听 loopback。远程开放、多用户宿主和公网登录不是首版范围。具体有效期、文件位置和轮换重叠窗口为 P。

| 阶段 | 权威动作与保存内容 | 失效/恢复语义及禁止事项 |
| --- | --- | --- |
| 初始化管理身份 | 本地安装入口在服务私有目录生成随机 bootstrap secret，私有目录/文件权限限制为 OS owner；仅告知来源路径 | 不把 secret 放 URL、日志或默认公开页面；无有效本地证明不能通过页面自建管理员 |
| Dashboard 登录 | 本地用户提交 bootstrap/管理凭据换取有限会话；服务认证后提供 HttpOnly、SameSite 会话 cookie，校验 Origin/CSRF；非 loopback 默认拒绝 | 刷新策略与会话过期明确；没有通过认证不能读取密钥或生成角色凭据；不能靠“请求来自 localhost”放行 |
| 签发角色连接 | 认证管理员选择项目、lead/reviewer、既有根绑定，生成随机作用域凭据；服务保存摘要、principal_id、grant/root epoch、过期和撤销状态 | 明文仅在受保护的配置交付中出现；CLI/MCP 配置引用私有文件或环境来源，不把 admin 凭据传给 agent |
| 执行身份 | 启动适配器为 launch_id 配置本次结果通道/nonce，输入只含本次授权数据及必要 provider/MCP 凭据来源 | 不继承 daemon 全量环境；结果通道只允许对应任务/执行交付，不能提交审核或管理服务；闭合后失效 |
| 撤销/轮换 | 事务更新凭据或 grant epoch，每次读写及长操作提交前核当前授权；受影响租约同事务撤销 | 撤销后旧连接下一次操作立即拒绝，不能只在 MCP 初始化时检查；已发出的远端副作用不保证撤回 |
| 根线程重绑 | 更新当前 root epoch，作废旧根专用凭据/会话及审核租约，签发新连接来源；历史事件归属不改 | 旧请求提交时 epoch 不匹配即拒绝；已排队旧通知可能仍到达但不能授权操作。登记 thread_id 不等于客户端真实在线证明 |
| 通知凭据 | Notifier 只使用受保护的既有客户端连接配置和目标绑定；提示文本无凭据 | 不通过创建新账号、拷贝登录态或把 API token 写入通知绕过失败 |
| 丢失管理凭据 | 受信 OS owner 走本地、留痕的重新签发/撤销入口 | 不提供未认证远程找回或自动扩大权限；不修改任务终态 |

撤销某个主线连接不隐含取消已提交任务，已授权 worker 工作仍按项目政策运行；撤销 reviewer 连接使其未提交判决无效、候选留队。停止业务执行需显式取消或项目执行授权操作，不能混同“停止访问”和“停止进程”。已提交判决的身份是历史事实，不因凭据轮换被抹去。

## 10 文件引用与秘密数据边界

**[D 待评审]** artifact_ref 是服务登记的对象标识，不是任意宿主路径或 bearer 权限。读取必须同时核对当前身份、项目、任务/候选可见性、保留记录、内容摘要及允许的对象范围。对象路径由服务解析，拒绝绝对路径、越界、符号链接逃逸及路径替换；按已打开的文件身份和有界读取核验，不能仅先做一次字符串前缀检查。损坏/缺失返回明确原因，不能退回读取“同名文件”。

provider/MCP 密钥放独立私有凭据存储，配置/DB 中保存引用，任务包和审计字段不包含明文。非敏感配置导出必须按允许字段重建；URL 中的 userinfo、敏感 query、环境变量值和认证头不能随导出、错误或诊断泄露。导入后重新配置凭据，不复制整个运行目录当作配置导出。

原生日志可能含工具意外打印的敏感信息。默认面向 agent 的诊断按字段白名单输出；原始日志私有保存，不向所有角色开放，读取和导出仍须相应权限。服务不能保证识别任意模型/工具打印的所有秘密，因此不能把简单正则脱敏叫“绝不泄露”。worker 只收到完成任务所需的密钥来源，避免把无关秘密带入日志风险面。

普通备份不等于可公开分享的导出：任务源码、原始日志和状态都可能敏感。备份受 OS 私有权限保护；默认不包含独立密钥存储，恢复后重新接线，缺凭据保持暂停。若用户明确选择带凭据的灾难恢复备份，则必须单独加密，解密材料不随备份存放；未实现这种模式时明确不支持。备份清单标出包含/排除的数据，不声称排除密钥文件就能让任意日志变成非敏感数据。

## 11 Dashboard 页面与操作框架

2. **动作可用性**：后端返回当前可用动作及禁止原因，前端用于展示；点击时后端重新验证权限与前置条件，不能信任按钮曾经可用。

4. **重复与竞争**：写入复用 request_key；配置采用期望版本检测冲突。保存后断线查询原结果，禁止换 key 盲重试；冲突要求重新读取并确认修改内容，不静默覆盖。
5. **状态同步与凭据**：使用[公共只读能力](#5-公共只读能力)快照/游标规则；切换身份、项目或表单版本时忽略迟到响应；遵守[凭据与连接生命周期](#9-凭据与连接生命周期)会话、CSRF 和私有凭据合同。

所属专题拥有业务语义，精确 schema 由唯一的类型化接口定义导出并校验，供前端类型与固定样例使用；不分别手写三份互相漂移的 HTTP、MCP 和 UI 状态定义。至少验证配置保存冲突、取消仍在处理、维护期间恢复派发被限制、升级断线后查询原操作、锁定后迟到响应和错误不显示为空列表。真实浏览器与真实后台联调结果单列，mock 只能证明前端处理合同样例。

## 14 V0 字段级接口合同

<a id="http-contract"></a>

#### 公共 HTTP 行为

- `/v1` 是协议主版本；响应 JSON 为 UTF-8。普通请求使用 `application/json`，错误使用 `application/problem+json`。GET 不接受业务请求体。拒绝重复 JSON 键、非有限数字、未知请求字段和类型强制转换；布尔值不当整数。除字段明确允许外，null 不等于未提供。数组顺序保留，目标和验收文本不做静默裁剪或 Unicode 规范化。
- agent 使用连接层自动附带的 `Authorization: Bearer ...`；Dashboard 使用管理会话 cookie，写操作同时核对 Origin 和 CSRF。agent 业务 JSON 不含 token/role/project_id；管理员项目作用域来自项目管理路径，或复用业务用例时明确的 X-Agentd-Project 头（规则见本节），由后端核权限；管理接线请求可包含其合同声明的范围字段。
- 除建立/退出管理会话外，写操作必须带 `Idempotency-Key`；CLI/MCP 的 `request_key` 映射该头，不属于 TaskSpec。读取不产生任务、领取、续租、模型调用或文件准备。
- 同步创建返回 201；查询/已完成操作返回 200；已持久受理但未完成返回 202，并给 operation_id 与查询位置。`202` 不是任务成功。cancel/resume/probe 均可先 202，之后用 operation 查询，而不是让 HTTP 请求一直等待。
- 配置变更请求使用明确的 `expected_version`，0 表示创建且目标必须不存在，正整数要求精确匹配。版本不符返回 409 `VERSION_CONFLICT`；此处不用 If-Match，再维护一套同义版本字段。返回当前可见版本及重新读取指引，不静默合并。
- 查询响应携带 [Meta](../../specs/agentd_v1/generated/API_REFERENCE.md#schema-meta) 定义的观察与版本信息。每次恢复数据库产生新的 store_epoch；旧游标、动作引用和未完成客户端预测不得跨 epoch 使用。已接入业务写请求带 `X-Agentd-Store-Epoch`，与当前值不符返回409 STORE_RESTORED，客户端不能自动改头后重放；登录/首次context不要求先知道epoch。
- 页结构由 models 的具体 Page 类型定义。游标绑定身份/项目、筛选、排序、插入高水位及 epoch；排序固定为创建序号和 ID。每页是同一次短读事务的观察，不承诺多页之间任务状态冻结；前端按 ID 更新，不能用一次翻页推导精确终态总量。管理总览快照在单次读取中一致；断线后重新读取当前快照。游标不合法/过期/跨身份返回 409 `CURSOR_INVALID`，不伪装空页。
- 认证失败 401；当前身份无该动作权限 403；不存在与不在可见项目内的对象统一 404；非法 JSON 400、字段语义错误 422；状态、幂等键和版本冲突 409；字节超限 413；媒体类型错误 415；准入容量耗尽 429；维护/必要服务不可用 503。任务自身等待依赖/容量属于成功提交后的状态，不把 submit 变成 429。

错误字段由 [Problem](../../specs/agentd_v1/generated/API_REFERENCE.md#schema-problem) 定义。不返回凭据、越权对象 ID 或原始敏感环境。request_recorded=null 表示提交结果未知，retry=query_request 要求先调用 B13 get_request_result；网络断线/未知内部错误不能解释为“操作未生效”；先查 request_key。`conflict` 则指本次新动作未被应用，已经应用的原请求结果单独返回。

参考：HTTP 的 201/202 与条件请求语义见 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.3)；错误结构及扩展成员采用 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html#section-3)。Idempotency-Key 的作用域、保留与重放是 agentd 自己的协议，不声称 HTTP 自动提供业务 exactly-once。

ErrorCode、字段长度、嵌套/数组上限、分块大小、租期和恢复策略候选值集中在 [models.py](../../specs/agentd_v1/models.py) 及其[生成参考](../../specs/agentd_v1/generated/API_REFERENCE.md)。它们仍是 D/P，实际部署须在启用前定案。不得在正文或框架隐藏默认值中再维护一套数值；改限额仍须保持合法已写内容可读取。

文本按原始 UTF-8 字节计量；解码显示不改证据原件。未知字段、重复 JSON 键、非有限数字及隐式类型转换拒绝。GET 读取不领取、不续租、不 ACK、不触发模型/构建；内容传输的 ReadGuard 仅保护并发删除。

TaskSpecInput 是调用方输入，TaskSpec 是提交时展开默认值并补入项目配置引用的冻结事实。客户端不能自报只读项目版本、模型和运行状态。V0 依赖非空明确拒绝；code 要求唯一固定 base，report 无需 commit。阶段、Execution 观察、审核观察与 operation.phase 分别表达，accepted/completed 不等于 Task passed。

提交时核对 difficulty.scale_id 是服务已经配置的量表，level 属于该量表；未知量表或不合法等级返回 422 INPUT_INVALID。接口不把范围偷偷固定为 1–5；字段类型校验不能代替注册状态检查。协议候选限额按部署的 limits_version 固定，由 context/admin snapshot 返回，不因框架升级而隐式改变。

ReviewDecision 必须覆盖冻结验收条件；PASS 不能含未满足或无法验证项，REJECT 至少有真实不满足项，环境不足使用 defer。结构、内容摘要和当前租约/候选/授权分别核验，任何一次格式错误都不增加审核轮次。

Artifact 读取按原始字节范围，EOF 空块与缺失不同；活动日志采用明确冻结段，不把可变路径当不可变对象。范围/权限检查及 ReadGuard 仍须由真实应用实现，JSON Schema 无法替代。

<a id="idempotency"></a>

#### 幂等结果与响应丢失

幂等作用域为 `(instance_id, scope_kind, scope_id, stable_principal_id, request_key)`；scope 是绑定项目，平台管理为 instance。方法、规范化路径、schema版本、业务请求体与 expected_version 都纳入请求摘要；token、连接句柄和HTTP追踪头不纳入。凭据轮换不改变 stable principal。含secret请求使用不可导出的服务端HMAC摘要，原始secret不写操作回执。

处理顺序：当前认证和对象范围校验 → 基本结构/限额校验 → 同 key 查询 → 无记录时在事务中保存请求记录及初始业务效果。相同 key 不同摘要409 KEY_REUSE；并发相同key只有一个operation。认证/语法/schema错误不占key，错误中 `request_recorded=false`；进入业务操作后若已形成结果（包括确定拒绝），保存回执，修改内容后须重新读取状态并使用新key。读取回执必须再次校验当前权限；不能通过历史回执绕过撤销。

“同 key 返回原结果”指**指向同一操作和已提交业务结果，不再执行一次**，不是强制所有HTTP字节永远不变。原submit结果.task_id不变，Operation的当前phase可以由accepted变completed；历史Review结果带committed_task_version，不能冒充当前Task快照。短效能力（review_handle/action_ref）另核当前有效性；若已失效可返回明确冲突及原operation引用，不能把原领取重放成有效新租约。

CLI/MCP在发送前持久记录选定连接、scope、请求和key；收到网络错误先B13，已找到则B14观察。B13暂未找到也只能原key原内容重发，不能以“查不到”推导原请求未在途。换root后旧凭据无效；当前授权的稳定身份只可取回允许的历史结果，不复活旧epoch动作或租约。

未决operation和幂等映射不可过期；完成记录可按保留政策压缩，但在对应业务历史仍保留时留下 key→摘要/结果引用或明确拒绝重放的tombstone。没有记录过期就允许同key重新执行的窗口。secret/大请求正文可按私有保留规则先行清理，不要求永久保存原始凭据。

<a id="management"></a>

#### 首次接入与管理行为

管理接口的精确结构见操作注册表。它们共用认证、CAS 和幂等规则，不扩展成通用 action 脚本或所有数据库对象的 CRUD。

| 动作 | 必须保持的行为 |
| --- | --- |
| 管理会话/快照 | 凭据不回显或入日志；会话用 HttpOnly/SameSite cookie，写操作核 Origin/CSRF。刷新后从受保护快照取当前 CSRF；响应 no-store。health 只证明入口存活，快照不主动运行探针 |
| 项目与输入根 | 管理员登记规范路径与稳定来源身份；机械 Git 检查不跑 hooks。提交过任务后不能把同 source ID 换成另一个仓库；默认值/资源注册版本在提交时冻结。V0 不接第二活动项目 |
| 私有凭据来源 | 密钥在私有存储先发布再登记引用；只返回来源、版本和可用性，普通导出不带 secret 路径。缺凭据等待，不自动登录；等价轮换不能偷换账号或 relay |
| 固定目录 | native-template/tool/mcp/recovery-policy 是有限固定类型，不是插件执行框架。列明成员复制后核摘要；登记不运行工具、MCP server 或模型。模板、工具、MCP 定义和策略生成不可变版本，活动任务所需内容不能删除 |
| worker 配置与退役 | 执行内容变化生成 config_id，准入/退休意图只改槽版本；保存不调用模型。减少数量转 draining，未完成绑定闭合后才 retired；已退休 ID 不复活。未知参数明确 unsupported，不静默忽略 |
| 派发暂停 | 只改变用户暂停，不解除维护/资源 hold，不停止已有执行 |
| 角色绑定 | 主线/reviewer 根不同，签发专用凭据并交付私有文件引用；重绑或撤销使旧代次和租约失效。CAS 版本在快照和回执中可读；丢响应找回原文件引用，不重签第二份 |
| 静态检查 | V0 只做字段、路径、可读性及声明匹配检查；CLI/付费模型探针须另有明确合同和资源准入，不从保存或 health 调用中暗自触发 |
| 任务资源覆盖 | 仅非终态可追加完整资源向量，先检查允许上限；当前并发预算不足可以保存等待。只在下一 Execution 生效，不热改 cgroup、不启动执行、不清次数 |
| 显式保留 | 管理身份取得或释放自己的 explicit_keep，覆盖 manifest 全部成员；不能释放活动输入、交付承诺等其他 pins。缺失/过期/回收对象不能靠设置标记冒充恢复 |

lead/reviewer 的项目来自连接，不能使用请求体或 X-Agentd-Project 覆盖。管理员复用项目业务接口时必须明确项目头；项目管理路径确定对应项目，catalog 用项目头，纯实例管理不带该头。后端仍核对象归属；不按浏览器最后打开的 tab 猜作用域。

首次可用链：U 安装并提供 bootstrap 来源 → 管理登录 → 登记仓库/输入根 → 凭据来源与固定目录 → 项目引用明确版本 → worker 配置 → 两个既有根的角色绑定 → 各自 get_context → 解除用户暂停 → submit。工具/MCP 可以为空，但项目确实需要的原生配置不能静默省略。

项目允许保存未完成接线的合法配置。只有 TaskSpec 必需的仓库、默认策略或固定引用无法确定时才拒绝提交；worker 忙、凭据暂不可用或 reviewer 离线不因此拒绝合法任务，任务仍可 queued。禁用配置的环境缺项不能妨碍 Dashboard 启动和修复。

Operation.result 由固定 kind 的结果类型定义，B13/B14 读取同一权威操作。领取、证据、续租可有专用直接返回视图，但不能另存第二份业务事实；历史 handle/activity_ref 不因重放变成当前授权。

#### 样例与验证入口

机器可读请求、错误和交付样例保存在 [examples](../../specs/agentd_v1/examples/)，使用 [契约检查命令](../../specs/agentd_v1/README.md)验证，不在文档中另抄 JSON。创建已完成只表示 Task 已排队；取消 accepted 必须继续查询到停止闭合；租约过期先重领原候选并复核，不能把旧报告套到新候选。review_reopen 只重新开放原候选，不启动 worker。
